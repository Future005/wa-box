# WA Box

Schedule WhatsApp messages to your existing WhatsApp groups, with random gaps between groups, for a whole team.
Lives at **https://wabox.example.com/wabox**.

- **Engine:** [Gateway](https://github.com/pedroslopez/whatsapp-web.js) on the `whatsapp-web.js` engine (a real headless Chromium running WhatsApp Web). Never Baileys.
- **App:** small Node.js app (scheduler + web page), SQLite, India time (IST) everywhere.
- **Deploy:** Coolify, Docker Compose build pack, this repo.

```
Team (browser) ──HTTPS──▶ Coolify proxy ──▶ wabox (scheduler + UI) ──private network──▶ gateway (headless Chromium → WhatsApp Web)
```

Only `wabox` is public. Gateway has no domain and no published port.

## Using it

1. **Log in** at `/wabox`. First admin is `admin@example.com`; the password is Coolify's generated `SERVICE_PASSWORD_ADMIN`
   (app → Environment Variables). You must change it on first login.
2. **WhatsApp tab (admins):** press *Connect / show QR*, then on the phone: WhatsApp → Settings → Linked devices → Link a device → scan.
   Use a spare number if you can.
3. **Schedule tab:** pick groups, write the message (optional image), choose date + time (IST), optional weekly repeat,
   and the random gap range. The preview shows when the last group will get it.
4. **Upcoming:** edit, *Send now*, or cancel. Live per-group progress.
5. **History:** every group, every send, with errors.
6. **Settings (admins):** it starts in **Dry run** (nothing is sent). Turn it off when you're ready.
7. **Team (admins):** add people as *member* (schedule only) or *admin*. They set their own password on first login.

## Safety rules (enforced on the server, can't be turned off)

- One job at a time, one message at a time.
- At least 30 s between any two sends (also across jobs). Each gap is random within the job's range.
- 0–60 s random jitter on start time; 2–5 s "typing…" before each message.
- Daily cap (default 30, max 60). Over the cap, the rest continues after midnight IST.
- Sends only to groups the number is currently a member of (checked right before sending). Unknown groups are skipped.
- Each job × group is sent at most once, even after restarts or crashes.
- WhatsApp disconnected → the queue waits. A job more than 120 min late (configurable) is marked *missed*, not sent at an odd hour.
- A failed send is retried once after ~90 s, then marked failed.

## Security

- HTTPS via Coolify, `HttpOnly; Secure; SameSite=Strict` session cookie, custom-header CSRF check, strict CSP, no framing.
- bcrypt passwords (min 10 chars), lockout after 5 wrong tries (15 min), login rate limit, 12 h idle timeout.
- Admin vs member roles; every action is in the activity log.
- Secrets are generated by Coolify (`SERVICE_PASSWORD_*`), never stored in git. Gateway key is shared only on the private network.
- No "anti-ban" packages, pinned dependencies, both containers drop Linux capabilities, app container is read-only.

## Coolify setup (once)

1. New resource → Private repository (GitHub App) → this repo, branch `main`, build pack **Docker Compose**, file `/docker-compose.yml`.
2. Domains: `wabox` service → `https://wabox.example.com/wabox`. Leave `gateway` **without** a domain.
3. Deploy. Coolify generates `SERVICE_PASSWORD_64_GATEWAYKEY` and `SERVICE_PASSWORD_ADMIN`.
4. DNS: `wabox.example.com` A record → the server IP.

Data lives in the `gateway-data` (WhatsApp login) and `wabox-data` (jobs, users) volumes. Back them up with Coolify's volume backups.
To update Gateway, set `GATEWAY_TAG` (default `latest`) and redeploy.

## Local run (dev)

```bash
cd app && npm ci
GATEWAY_URL=http://localhost:2785 GATEWAY_API_KEY=... ADMIN_PASSWORD=change-me-now COOKIE_INSECURE=true DATA_DIR=./data npm start
# open http://localhost:3000/wabox/
```
